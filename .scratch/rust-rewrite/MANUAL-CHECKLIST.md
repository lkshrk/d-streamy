# Manual checklist (human-only)

Agents append items here; each needs exact commands and expected result.

- [ ] Live Go Live on real Discord with burner account: `DSTREAMY_TOKEN=… dstreamy stream --guild … --channel … --target test-pattern` → viewer sees pattern + hears tone, H264
- [ ] macOS real capture (Screen Recording permission): grant Screen Recording to the terminal, then `cd rust && cargo test -p dstreamy-capture-macos --test screencapture -- --ignored --nocapture --test-threads=1` → 4 tests pass: `lists_displays_and_windows` prints `display:<id>` and `window:<id>` targets, `captures_main_display_as_h264_with_audio` decodes the H264 AUs and prints a non-zero audio count while sound plays, `captures_cropped_display_as_h265` and `captures_first_user_window` start with a keyframe. Without the permission SCShareableContent returned windows but no displays and no frames (seen 2026-10-21).
- [ ] HEVC VideoToolbox on Apple Silicon (CI runners may lack an HEVC encoder, and then `h265_keyframe_has_parameter_sets` only prints a skip): `cd rust && cargo test -p dstreamy-capture-macos --test videotoolbox h265 -- --nocapture` → passes with no `skipping:` line (seen passing on an arm64 Mac 2026-10-21).
- [ ] macOS `dstreamy targets` lists displays (Screen Recording permission granted to the terminal): `cd rust && cargo test -p dstreamy-cli --test cli targets_list_macos_displays -- --ignored --nocapture` → passes; `--json targets` contains at least one `display:<id>` row.
- [ ] Linux Wayland portal + PipeWire capture (needs `gstreamer1.0-pipewire`, `gstreamer1.0-pulseaudio`, `gstreamer1.0-plugins-ugly`, a running desktop session and pipewire-pulse): `cd rust && cargo test -p dstreamy-capture-linux --test portal -- --ignored --nocapture` → pick a screen in the dialog, play some audio; the test passes (≥30 decodable AUs, first a keyframe, Opus frames present, restore token returned) and the second start reuses the token without showing the dialog. The printed `encoder:` line names the selected encoder.
- [ ] Hardware encoders: VA-API, NVENC selected and streaming
- [ ] Sign off removal of Swift/Bun code (issue 14)
- [ ] First Rust release run (needs a tag, so human-triggered): bump `version` in `rust/Cargo.toml` if needed, then `git tag rs-v<version> && git push origin rs-v<version>` → the `Release (Rust)` workflow passes `version`, `check` (macos-26, ubuntu-24.04, ubuntu-24.04-arm), all four `build` jobs (incl. Rosetta install + x86_64 smoke run on macos-26 and the native `ubuntu-24.04-arm` job) and creates a prerelease (not latest) with four `.tar.gz` + `.sha256` assets. Download one on each platform and run `dstreamy --version`; on Linux check `ldd dstreamy` has no missing libraries on Ubuntu 24.04.
- [ ] First `rs-v*` tag run: rustup is present on `ubuntu-24.04-arm` (the workflows run a bare `rustup toolchain install`; the `check` and aarch64 Linux `build` jobs fail at that step if it is missing).
- [ ] Homebrew formula: copy the filled `Formula/dstreamy.rb` that the release job prints into the run summary (version and both macOS sha256 values set) over the repository file, then `brew install --formula ./Formula/dstreamy.rb` (or via a tap) → installs and `brew test dstreamy` passes. Publishing to `lkshrk/homebrew-tap` is a separate decision.
